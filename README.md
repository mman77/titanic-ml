# Titanic ML (seaborn sample) + Kaggle-ready notebook

Goal: predict survival (binary classification) with an honest methodology:
imputation inside the Pipeline, model selection by cross-validation on the
train split only, test set touched once.

Data: `titanic.csv` is the seaborn sample (891 rows). The Kaggle competition
files (`train.csv` / `test.csv` with Name/Ticket/Cabin) are used only inside
`titanic.ipynb`, which also extracts `Title`/`Deck` when they exist.

## Run (Windows: `py -3.12 ...`, elsewhere: `python ...`)
```
pip install -r requirements.txt
py -3.12 01_download_data.py
py -3.12 02_explore.py
py -3.12 03_clean.py      # must run before 05-09
py -3.12 04_analyze.py
py -3.12 05_train.py
py -3.12 06_tune.py       # writes the model + best_params.json (must run before 07-09)
py -3.12 07_evaluate.py
py -3.12 08_predict.py
py -3.12 09_advanced.py   # writes metrics.txt
```
`titanic_clean.csv`, `titanic_best_model.pkl`, `plots/` are regenerated by the
scripts above (not stored in git). `07`/`08` stop with a clear message if the
model file is missing.

## Results
Repeated stratified CV (5 folds x 3 repeats) on the train split (n=712);
every model uses its own tuned params from `06`; baselines go through the
same CV.

| Model | CV-AUC | CV-accuracy |
|---|---|---|
| Dummy (majority) | 0.500 | 61.7% |
| SexRule (female -> survived) | 0.770 ± 0.027 | 78.9% ± 2.3 |
| LogisticRegression | 0.855 ± 0.024 | 80.8% ± 2.9 |
| RandomForest (tuned, depth 6) | **0.879 ± 0.026** | 82.4% ± 2.4 |
| HistGradientBoosting (tuned) | 0.871 ± 0.032 | 82.9% ± 3.3 |

Paired on identical folds (winner = RandomForest):
- vs SexRule: +0.109 AUC, better in 15/15 folds
- vs LogisticRegression: +0.024 AUC, better in 15/15 folds
- vs HistGradientBoosting: +0.008 AUC, better in 11/15 folds -> not decisive
  (treat RF ~ HGB)

Holdout, single look (n=179, roughly ±6%):
- RandomForest: 78.2% (140/179), AUC 0.844
- SexRule: 77.7% (139/179), AUC 0.753

Reading: the real gain over the one-line rule is in ranking quality (AUC,
~+0.11 in CV). Holdout *accuracy* differs by a single passenger, so do not
quote it as an improvement. Full output: `metrics.txt`.

## Files
- `common.py` shared seed/paths/features/preprocess/CV/baselines/model loader
- `01..04` download / explore / structural clean / analysis (+ 1 plot)
- `05` baselines + models + permutation importance
- `06` GridSearchCV (ROC-AUC) for LR/RF/HGB -> best model + `best_params.json`
  (tuned params of all three models)
- `07` confusion matrix + ROC + error analysis (with group sizes)
- `08` validated single-passenger prediction (`age=None` allowed)
- `09` repeated-CV final report -> `metrics.txt`
- `titanic.ipynb` same methodology, Kaggle-ready (writes `submission.csv`);
  outputs saved from the local seaborn run, re-run it on Kaggle

## Limitations
- n=891 / holdout=179: 1-2% gaps between models are noise, not signal.
- The CV score is also what tuning and model selection optimise, so it is
  slightly optimistic; the holdout is unbiased but noisy. Nested CV would fix
  this.
- Overfitting: default RF in `05` reaches ~98% train vs ~80% test; the tuned
  depth-6 RF reaches ~89% train vs ~78% test. CV is the number to trust.
- `sex` dominates: permutation importance 0.189 vs <= 0.013 for every other
  feature. The model is mostly a sex rule plus small refinements.
- The seaborn sample has no Name/Ticket/Cabin (no Title feature locally), and
  107 rows are exact duplicates of other rows, so identical passengers can
  land on both sides of the split.
- Notebook numbers differ slightly from the scripts (different column order
  -> different RF randomness); do not compare them digit by digit.
